# Complex workflows and editable charts — November 7, 2026

Charts does **not** implement all of tradingview.com. This iteration adds a real
interactive chart editor, model-controlled edits, batched indicator snapshots
and a stock screener with common numeric filters. Alerts, Bar Replay, order
execution and Pine compilation are [explicit TODOs](../../docs/todos.md).

## Tested workflows

The same local Qwen 35.5B model and Pi harness were used. Each result was checked
against returned data and, for the editor, the browser's actual state. A plausible
answer alone does not count as a successful operation.

| Request | Initial Qwen result | Revised result |
| --- | --- | --- |
| Three-symbol overlay, daily October, then 90 days hourly | One call per turn, but omitted the new period and invented intermediate points | The primary reference retrieved 31 daily and 2,160 hourly observations; Qwen's narrative is not considered reliable |
| BTC and ETH: daily/hourly RSI, MACD line/signal and EMA200 | 14 calls, hit the attempt limit without completing the table | One `snapshot` call, all requested values returned |
| US stocks: cap >10B, average volume >1M, RSI 30–45; first 5 then next 5 | 24 attempts across two turns, guessed incorrect field names and switched to a different screen | Two `screen` calls, correct filters, sort and offsets, no repeated symbols |
| ETH/BTC formula, rebasing, drawdown and rolling correlation | Did not complete | These calculations are still outside the current tools; no fabricated statistics are accepted |
| Ordinary and Heikin Ashi hourly candles | Three calls, including a busy retry | Both datasets retrieved and distinguished as ordinary/synthetic; primary reference needed two sequential calls |
| Bounded BTC/ETH quote stream | One call | Updates returned and subscription stopped; it does not imply ongoing monitoring |
| Create an interactive BTC/longs chart; add SMA/RSI; switch to hourly candles, raw log scale, remove longs/SMA | Early editor trials exposed argument and identifier problems | **Three calls, all three operations verified in actual state and browser** |

The raw-data workflows above used anonymous real provider reads. They are not
claims of paid data access, private Pine availability or identical TradingView
UI behavior. Snapshot values can change between runs. Qwen still sometimes
adds unsupported explanations or formats a large market cap incorrectly; the
direct structured results and rendered chart remain authoritative.

## Editor verification

The final Qwen conversation was:

1. Create BTCUSD/BTCUSDLONGS, daily YTD, percentage change, and return the link.
2. Keep that view; change its title/colors; add BTC SMA20 and RSI14 in two panes.
3. Keep that view; use BTC-only hourly ordinary candles for the last calendar
   month, raw prices, logarithmic scale, RSI14 retained and SMA/longs removed.

It used `view create`, `view update`, `view update`. Final state checks confirmed:

- The view ID and URL stayed the same.
- Timeframe `60`, candlestick style, raw prices, log scale.
- BTCUSD only and RSI14 in the separate pane.
- Exactly **744 hourly bars**, Oct 1 00:00 through Oct 31 23:00 UTC.
- The browser rendered the final configuration with no JavaScript errors.

A separate browser test verified CLI-to-browser updates, browser-to-CLI edits,
two panes, rapid two-point drawing, saved zoom and actual canvas rendering. It
also passed against the public HTTPS link. The automated suite has 64 passing
tests, including argument validation, retained state after invalid/stale edits,
and local indicator warm-up semantics.

See [machine-readable results](complex-results.json),
[the complex prompts](complex-scenarios.mjs), [editor prompts](editor-scenarios.mjs)
and [the optional browser test](browser-check.mjs).

## Changes based on failures

- A dated view automatically sizes history within its 5,000-bar ceiling. Qwen
  had estimated October as 720 hours; that would silently omit a day. The tool
  now requests enough bars for the actual calendar window.
- `snapshot` gets multiple indicators/timeframes together; `screen` translates
  common cap/volume/RSI filters into verified provider fields. The original raw
  tools remain available.
- View IDs are shorter. New study/drawing IDs are optional and generated by the
  host. Missing properties on existing IDs are preserved. Primary chart type
  and explicit removals have direct options.
- `actualView` describes the applied state. It is possible for a model to omit
  a requested change; consumers should check this state rather than its prose.
- Unchanged browser polls return a tiny revision response instead of repeatedly
  sending the entire chart dataset.

## Reproduction and limits

Use `CHARTS_EVAL_SCENARIOS` to select the complex or editor module, and
`CHARTS_EVAL_LIVE=1` for public reads. Set `CHARTS_EVAL_EDITOR=1` only for the
editor test, which explicitly permits temporary view creation/edits/closure.
It still blocks account mutations. Run cases sequentially to avoid competing
for the model.

For browser verification on a development/client machine, set
`CHARTS_PLAYWRIGHT_MODULE` to an installed Playwright module, optionally set
`CHARTS_BROWSER_EXECUTABLE`, and run `node .../browser-check.mjs`. This creates
a temporary test view and closes it afterward. Browser tooling is not installed
or run on the Orin.

One early editor trial was invalid because the evaluation adapter added an
`auth` option to local-only view tools. Those failures are excluded. The harness
now pins Pi to the selected Node executable through `PATH` and records runtime
metadata. The final editor run used Node 24.22.1 on macOS ARM64. Earlier exploratory
Pi runs used Node 23 through its shebang; the production test suite used Node 24.

These are iterated development prompts with one final measured conversation,
not an estimate of accuracy on arbitrary unseen prompts. Full account-layout
editing, advanced footprint/volume-profile data and arbitrary statistical
formula execution are not established by this work.
